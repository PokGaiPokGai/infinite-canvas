# 本机运行与开发

根目录仅保留通用的 `启动无限画布.cmd`、`启动开发版.cmd`、`停止无限画布.cmd`。功能名称、验收批次和端口不再生成受 Git 跟踪的启动脚本。

## 目录边界

| 位置 | 用途 | Git |
| --- | --- | --- |
| `local/` | 公共运行程序、桥接、配置模板、可重复测试 | 跟踪 |
| 每个检出的 `.local/instance.json` | 当前 worktree 的开发端口 | 忽略 |
| 每个检出的 `.local/启动开发版.cmd`、`.local/停止开发版.cmd` | 当前 worktree 的双击入口 | 忽略 |
| 每个检出的 `.local/runtime-*` | 日志和实例所有权记录 | 忽略 |
| 主检出 `.local/app-data/` | 共享业务数据库与历史副本 | 忽略 |
| 主检出 `.local/builds/shared/` | 本机共享版静态产物及版本清单 | 忽略 |
| `web/dist/` | 默认浏览器存储版产物 | 忽略 |

`.dockerignore` 同时排除本机目录、嵌套 worktree、依赖和构建缓存。Git 忽略规则不能替代 Docker 的上下文规则。

## 新建开发入口

在已建立的功能 worktree 根目录执行，选择未被使用的端口：

```powershell
pnpm --dir web install --frozen-lockfile --ignore-scripts
node local/runtime.mjs init --port 3080
node local/runtime.mjs start
```

随后可双击该 worktree `.local/启动开发版.cmd`。`init` 不创建分支、不下载工具、不复制数据库；已有不同端口的配置会拒绝覆盖。功能检出必须显式配置。`main` 固定使用 3000 的本机共享版，拒绝配置其他开发端口；在 main 点击通用开发入口或执行 `start` 也会使用同一份 3000 构建。

前端读取当前检出的源码并热更新。标题为 `<分支短名> · <端口> | 无限画布`；身份接口统一为 `/__canvas`，返回真实分支、提交、启动提交、源码目录、端口、模式和数据目录。无法读取 Git 时明确显示未知。

启动器不会自动创建 `node_modules` 联接。每次启动都比较当前锁文件、依赖目录所属检出的声明，以及 pnpm 已安装锁文件；手动共享依赖也须通过这些检查。修改依赖的分支应安装自己的依赖，不能在指向其他 worktree 的联接上安装。

## 共享服务归属

开发窗口默认沿用主检出的共享数据及 3002 后台。后台代码、数据库和后台所有权记录均属于主检出；功能分支只请求启动或复用它，不再用功能分支后台代码管理主数据库。ComfyUI 保持原有 8188 服务。

```powershell
node local/runtime.mjs status
node local/runtime.mjs stop
# 在已确认没有任务需要继续时，单独请求停止共享后台：
node local/runtime.mjs stop --bridge
```

`stop` 只停止当前检出的前端；主检出还会处理其正式前端。后台需显式 `--bridge`，有生成或画布执行任务时拒绝停止。请求会核对进程、启动时间、目录和私有所有权令牌；端口被占用但来源不明时拒绝接管，不按端口强杀。令牌只保存在被忽略的运行记录中，不由身份接口返回。

旧版服务没有统一身份协议时不会被接管。需要退役旧入口时，在其所属检出运行 `node local/runtime.mjs stop --legacy`；显式加 `--bridge` 才处理该检出原先拥有的空闲后台。迁移停止仍核对 PID、启动时间、可执行文件和完整配置路径，不删数据或日志。合并本轮整改后，应先核对并关闭旧入口拥有的服务，再启动新入口；不能把启动失败解释成需要强杀旧进程。整改未合入主检出时，功能分支不会替换原有后台。

## 正式本机共享版

只在 main 主检出使用正式入口。main 每次更新后及时构建并核对运行版本，日常统一通过 `http://127.0.0.1:3000/canvas` 查看。双击 `启动无限画布.cmd` 打开已有 Edge/Chrome 应用窗口；没有浏览器时只报告，不安装。

```powershell
pnpm --dir web run build:local
node local/runtime.mjs serve
```

本机产物保存在 `.local/builds/shared/`，`canvas-build.json` 记录存储模式、Git 提交、源码指纹与构建时间。启动会拒绝缺失、错误模式或过期产物。默认 `pnpm --dir web run build` 仍输出浏览器存储版到 `web/dist/`，不会覆盖本机产物。

main 更新后的收尾必须包含构建和运行版本核对，不再等待另一次构建授权。先构建成功，再通过 `stop`／`serve --no-browser` 切换归属已确认的主前端；仅在后台代码或启动提交变化时核对活动任务并显式切换 `--bridge`。有任务时保留运行并报告，不能强杀。浏览器标签保持打开，刷新 3000 即可使用新版；构建或切换失败必须明确报告。该约定由开发收尾执行，没有安装后台监听器或 Git hook。

## 数据与恢复

画布、素材、生成历史和核心配置保存在主检出的 `.local/app-data/canvas.sqlite`。可能包含 API Key 或 WebDAV 凭据，不复制到模板、仓库或测试夹具。首次浏览器迁移仍保留源数据和冲突副本；共享写入继续使用版本号及冲突保护，不等同于云同步或多人实时协作。

数据库内部历史与正文在同一个文件中，不能替代独立备份。日常导出重要画布；需要文件级备份时先妥善停止相关服务，再备份完整数据目录。应用窗口的浏览器配置位于 `.local/app-window/`，不再是业务数据的唯一来源。

已打开画布收到其他窗口修改后需要重新载入。含当前版本不支持的节点（包括嵌套流程）时，会停止载入和自动保存，保留导出原画布、管理插件和返回列表的入口。旧分支须纳入此保护才能生效，不能由新版后台替旧前端补齐功能。

批处理／复用流程使用同一节点的跨窗口执行所有权：共享版由后台连接持有，浏览器存储版使用 Web Locks。重复执行立即拒绝，不排队、不自动重试；载入不再把其他窗口运行中的行标为失败。连接丢失或取消只停止本页等待，已交给模型服务的任务仍可能完成，继续前需核对已有结果。

## 现有工具配置

- ComfyUI：沿用已有服务、模型与自定义渠道脚本。首次空白配置可使用 `comfyui-config.json`；已有渠道不得重新导入整份配置覆盖凭据和偏好。`node local/make-config.mjs` 只重建无凭证模板，不更新已保存的渠道。
- Codex：复用本机 CLI 登录，`CODEX_CLI_JS` 可指定已有 CLI 入口；不搬运登录文件，不安装或更改 CLI。原图与任务记录在主检出 `.local/codex-image/` 和 `.local/codex-text/`。停止等待不保证后台取消，恢复结果不自动补回原画布。
- Krita：沿用已有连接；节点未连接时仍可见。测试不向真实文档写入。
- Blender：见 [Blender Link](blender-README.md)。真实连接和 `.blend` 写入必须独立确认，模拟桥接通过不等于实机验收。

## 验证与合并收尾

前端仅采用 `web/pnpm-lock.yaml`，包管理器由 `packageManager` 固定。离线行为检查统一使用已有 Node 24.14+ 与 Python，无需 Bun：

```powershell
pnpm --dir web run check
```

该命令运行前端行为、运行身份、构建指纹、执行所有权、模拟工具桥接和 Krita 延迟测试；不构建、不部署、不调用真实模型或 Blender。Blender 脚本测试需要独立 Blender 测试进程，不包含在普通 Python 检查中。详见 [验收约定](QA.md)。

合并前核对两边 Git 状态及所需验证；获准后用 `--no-ff`。合并后核对父提交，及时构建 main 并核对 3000 的运行身份及产物版本。仅切换本项目归属明确的 main 服务；旧 worktree 是否仍使用及数据保留另行核对。删除分支、归档 worktree 和推送仍分别按授权执行。

本轮验证结果与未验收范围见[待测试记录](../docs/content/docs/progress/pending-test.zh-CN.mdx)。
