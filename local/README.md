# 本机共享画布、应用窗口与生成

部署目录为仓库根目录。双击桌面或开始菜单中的 `Infinite Canvas.lnk`，或根目录的 `启动无限画布.cmd`，会先隐藏启动本机服务，再打开独立 Edge 应用窗口；也可在普通浏览器或 Codex 内置浏览器打开[我的画布](http://127.0.0.1:3000/canvas)，读取同一份本机业务数据。关闭应用窗口不会停止服务。`停止无限画布.cmd` 只停止启动器拥有的画布和空闲的本机 Node 服务；有活动生图任务时保留 Node 服务，共用的 ComfyUI 始终保持运行。

前端固定使用 `http://127.0.0.1:3000`，ComfyUI 使用现有的 `http://127.0.0.1:8188`。现有 `127.0.0.1:3002` Node 进程同时提供 Codex 生图／文本桥接和 `/storage` 共享存储。`local/vite.config.ts` 将网页同源 `/local-data/*` 转为 Node 的 `/storage/*`，`/codex-image/*` 转给 Codex 桥接，`/comfy/*` 转给 ComfyUI。服务都只监听本机，不改 ComfyUI 原配置，也不启动通用跨域代理。

## 共享数据与迁移

通过本目录专用配置构建后，普通浏览器、Codex 内置浏览器与独立应用窗口使用同一份本机数据。数据库为仓库内 `.local/app-data/canvas.sqlite`，SQLite schema 为 1；画布、资产、生成历史及原始图片、音视频的完整二进制内容保存在该数据库中，图片以 Blob 字节保存，不依赖某个浏览器的配置目录。

AI 渠道与偏好、提示词来源和主题这 3 个核心持久化配置也改为共享。设置可能包含用户填写的 API Key、WebDAV 凭据和自定义脚本，保存在被 Git 忽略的本机数据库；前端仍按所选渠道使用配置发起请求。本次不复制、导出或搬运 Codex 的登录文件与令牌。

每个浏览器配置目录第一次打开共享版时，会自动把原有业务数据完整上传到迁移暂存区，再提交到共享库。成功后记录迁移标记；再次打开不会重复导入，原浏览器的源数据不会被删除。同 ID 内容相同时复用；内容不同时保留共享库当前内容，并保留完整源副本供恢复，不静默覆盖现有画布或配置。该过程只在本机发生，不代表云同步。

数据库同时保留 `storage_versions` 中的完整版本与冲突副本，以及 `storage_imports`、`storage_import_items` 中的迁移清单和完整暂存内容；这些记录和原图都在同一个数据库，并非另一份独立备份。未知 schema、无法识别的原有数据库或写入冲突会停止覆盖，而不是重置数据。日常仍应导出重要画布，并另行备份本机数据。

另一个窗口保存后，画布库列表会在当前没有输入、待保存或错误时更新；已经打开的编辑页显示「另一窗口已更新本机数据，请重新载入后继续编辑」。同一项目存在相互冲突的修改时，服务返回 409 并保留冲突副本，当前窗口提示保存未完成，可先「导出未保存内容」，再处理与重新载入。这是带冲突保护的本机共享，不能当作多人实时协作。

`image_previews` 缩略图、`prompt_cache` 缓存，以及布局、Agent 连接等窗口偏好继续留在各浏览器配置目录；这些缓存不作为共享业务数据的权威来源。独立应用窗口的浏览器配置目录为 `.local/app-window`，不再承担唯一业务存储。

## 配置

共享库已有渠道时，新浏览器无需重复配置。仅在共享库首次空白、需要初始化 ComfyUI 渠道时，进入「配置 → 导入配置」，选择本目录的 `comfyui-config.json`。这份无凭证配置使用已有的自定义模型脚本，实际走 ComfyUI 原生 `/prompt`、`/history`、`/view`、`/upload/image` API。界面的协议枚举仍为 OpenAI，但请求由脚本接管；`local-comfyui` 只是满足界面校验的公开占位文字，不是密钥，也不会发送。

导入会整体覆盖当前共享的渠道、WebDAV 和提示词来源设置，影响连接这份本机库的其他窗口；只在首次空白配置时使用整套导入，已有渠道优先在界面单独新增或修改。脚本更改后运行 `node local/make-config.mjs` 只会重建无凭证导入文件，不会自动更新已保存的渠道。本次通用 ComfyUI 脚本升级也遵循此规则：已有渠道须在模型配置中单独更新脚本，不能为此重新导入整份配置。Git Fork 仅保存程序，本机数据库与原图目录不入 Git，日常请导出重要创作备份。

默认使用已有的 `dreamshaperXL_lightningDPMSDE.safetensors`：6 步、CFG 2、DPM++ SDE / Karras。通用「生成配置」可手动调整负面提示词、改绘强度、步数、CFG、种子、采样器、调度器和风格权重，也可选草稿转绘／保留结构细化参数预设。无底图时仍可文生图；有图时只允许一张「参考」或「构图」底图进行改绘（默认强度 0.65），多张「风格」图片依次进入已安装的 SDXL IP-Adapter，并均分设置的风格权重。配色、角色、姿态等其他图片角色目前只有提示词描述，本脚本会在提交前明确拒绝，不能当作实际模型控制。缺少 IP-Adapter 或 CLIP Vision 模型时风格任务不会提交；不自动安装扩展或模型。

自动尺寸下文生图为 1024×1024，改绘沿用底图尺寸；VAE 输入对齐到 8 像素倍数，若原尺寸不对齐，输出再缩放回请求尺寸。明确选择尺寸时使用界面给出的尺寸。生成数量传给 ComfyUI 批次，未额外裁剪数量或缩小尺寸。「质量」档位不是本工作流的采样参数，透明背景不受此工作流支持。多风格图与实际创作效果尚未实机验证；此前验证的单参考图改绘结果只对应旧脚本。

轮询沿用应用已有默认值：每 2.5 秒查询，最多 5 分钟；未新增重试。取消页面任务会停止本页等待，不调用 ComfyUI 全局中断接口，已经排队或运行的后端任务可能继续完成。运行时错误会显示 ComfyUI 任务错误。

## 启动方式

### 体验优化分支预览

双击仓库根目录的 `启动体验优化版.cmd`，隐藏启动开发服务并在浏览器打开 `http://127.0.0.1:3010/canvas`。后续修改前端源码会热更新，无需重新构建；再次双击会复用本入口已经启动的服务。关闭浏览器不会停止开发服务。

此入口使用本分支的 `local/vite.canvas-ux.config.ts`，前端源码来自本 worktree；通过同源代理复用原版 `3002` 服务的共享数据库、Krita 和 Codex 桥接，以及已有 ComfyUI。原版 `3000` 继续可用，两边保存会影响同一份数据，已有冲突保护继续生效。服务未运行时调用主检出的启动器，不在 worktree 新建另一份数据库。若此前用过浏览器独立存储，首次切换沿用现有迁移流程，保留迁移源及冲突副本。

分支代理先检查请求的 Host、Origin 与浏览器来源，再将合法的分支 Origin 转为现有服务接受的本机 Origin；不放宽后端白名单，不向局域网开放服务。Krita 节点注册与存储模式独立：普通网页模式也显示节点，没有连接服务时面板显示未连接。

首次启动时，若 worktree 没有依赖且锁文件与主检出一致，会为 `web/node_modules` 创建指向主检出已安装依赖的目录联接，不下载或安装软件；锁文件不一致或依赖不存在时显示错误。端口被其他进程占用时拒绝启动，不停止该进程。日志位于 worktree 的 `.local/canvas-ux-*.log`。启动后检查分支身份、共享存储与 Krita 状态接口，Krita 未打开时仍可进入画布。

后续每个分支都必须维护自己的双击入口、运行配置和占用不同端口的前端服务，明确数据／桥接来源并更新本节说明，不能只创建 worktree 而沿用原版前端或静默退回空白预览。

### 本机共享版

打开画布不要求 ComfyUI 先就绪。使用通用「生成配置」中的本机 ComfyUI 渠道前，应确保已有的 ComfyUI 已启动；若仍使用旧 Krita 专用预设接口，它会沿用 `COMFYUI_START_SCRIPT` 或本机不入库的 `.local/machine.json` 中的 `comfyStartScript` 启动逻辑。新工作流不安装 ComfyUI、节点或模型，也不更改 Krita 的连接。

前端依赖使用 `web/pnpm-lock.yaml`。在仓库根目录执行下面的本地专用构建命令：

```powershell
cd web
pnpm install --frozen-lockfile --ignore-scripts
pnpm exec vite build --config ../local/vite.config.ts
```

更新后必须继续使用 `local/vite.config.ts`，使 `VITE_LOCAL_SHARED_STORAGE=1` 写入构建产物。默认的 `pnpm run build` / 默认 Vite 配置仍用于原站浏览器存储模式，不能替代这一步，否则会切回浏览器各自保存。现有启动器继续运行 `web/dist`；上游 npm 锁文件与依赖不一致，部署没有重写它。

校验范围：本地专用 Vite 构建已通过，保留上游已有的大包与动态导入提示。全项目类型检查仍受未改动的 `web/src/components/layout/model-script-editor.tsx:58` 中 `content` 字段旧错误阻断，不能写成全量类型检查通过；本次新增存储模块的严格类型检查单独通过。这些检查不能替代实际迁移、跨窗口保存和桌面启动验收。

## 文件位置

ComfyUI 原图保存到其配置的 `output/InfiniteCanvas/Canvas_*.png`，参考图上传到其 `input/InfiniteCanvas`。具体根目录由用户自己的 ComfyUI 配置决定。网页成功接收的原图、画布和生成历史同时保存到 `.local/app-data/canvas.sqlite`；Codex 另保留下文的任务原图目录。运行日志、机器专属启动器路径、进程记录、数据库和应用窗口配置都放在本仓库的 `.local/`，由 `.gitignore` 与 `.git/info/exclude` 排除。

## Codex 订阅生图

本地部署新增独立的「Codex 订阅生图」渠道，与原 ComfyUI 渠道并存。在生图工作台或画布中选择对应模型即可切换；本次不整体导入或覆盖已有渠道、偏好和创作记录。

### 连接与登录

本机 Node 桥接只监听 `127.0.0.1:3002`，网页通过同源 `/codex-image/*` 访问。自定义调用脚本使用原始 `request` 创建任务并轮询，不发送 Authorization 或 API Key。渠道中的公开占位文字仅用于通过现有界面校验，不是凭据。

桥接调用本机已安装的 Codex CLI，固定使用 ChatGPT 登录方式，清除子进程继承的 OpenAI API Key 和第三方地址等相关环境变量，并忽略用户模型调用配置。它不复制、导出或搬运登录文件与令牌，不将登录凭据写入渠道或发送到浏览器。若 CLI 未登录，需要用户本人通过 `codex login` 完成登录。

这条通道使用 Codex 的内置生图能力；界面的模型名称是渠道标识，不能据此保证底层一定为 `gpt-image-2`。尺寸、质量和透明背景要求会提交给生成任务，但精确像素尺寸与透明通道不能保证，实际结果以原图为准。请求多张时逐张生成；参考图通过 CLI 的 `--image`（`-i`）传入，参考图改绘和多张生成尚待验证。

### 原图、历史与任务恢复

每个任务保存到仓库的 `.local/codex-image/jobs/<任务 UUID>/`：第一张原图为 `0.png`，后续图片依次编号；`job.json` 保存提示词、请求参数、任务状态、实际尺寸与图片 SHA-256。任务目录不入 Git；生成提示词与参考图按当前生图流程交由 Codex 处理。共享版网页正常收到的成功结果保存至 `.local/app-data/canvas.sqlite`，供各窗口的生图历史和画布读取；任务目录仍独立保留生成原图。默认站点构建仍使用浏览器 IndexedDB。

打开[本机 Codex 生图记录](http://127.0.0.1:3000/codex-image/records)可查看任务状态与下载完成的原图。刷新画布、停止页面等待，或达到现有轮询的默认 5 分钟上限后，后台任务仍可能继续；稍后刷新记录页查看结果即可。页面停止等待不等于后台任务被取消；桥接未新增自动重试，服务中断也不会自行重新生成或再次消耗额度。

记录页提供的是本机任务结果恢复查看。工作台原来显示的失败记录不会自动变成成功，也不会自动将后续完成图片补回原画布。需要时从记录页下载，再通过应用现有的图片导入功能添加到画布或资产。请同时保留本机任务目录与共享数据库，并定期导出重要创作内容。

### 启动与停止

根目录的 `启动无限画布.cmd` 与桌面、开始菜单入口都通过隐藏引导启动服务，再打开独立应用窗口。启动器先启动或复用提供生图与共享存储的 Node 进程，再启动或复用画布，并核验生图和存储接口；ComfyUI 按 Krita 本机生成需求准备。CLI 入口默认由本机 `codex` 命令位置推导，可用 `CODEX_CLI_JS` 环境变量指定；不修改已安装 CLI 或登录配置。

`停止无限画布.cmd` 只停止启动器记录且所有权仍匹配的画布和桥接进程。若桥接仍有活动生图任务，会保留桥接并显示说明，确保任务有机会继续写盘；完成后可再次执行停止。共享 ComfyUI 后端始终保留。端口上已有其他应用或服务身份不匹配时拒绝复用，不关闭该应用。

## Codex 订阅文本（本机构建）

在画布新建或打开「生成配置」，切换到「文本」，选择本机的「Codex 订阅文本」模型，提供文字提示词后手动点击「开始生成」。完成的文本由现有画布流程显示和保存，并可从配置节点的文本输出端口连接下游；不会自动执行生图或 Krita 写回。现有 ComfyUI 和 Codex 订阅生图渠道继续可用。

文本脚本 `local/codex-text.js` 经同源 `/codex-image/text/jobs` 提交任务，再读取 `/codex-image/text/jobs/<任务 UUID>`。本机桥接复用已登录的 Codex CLI 和 ChatGPT 订阅，不要求网页提供真实 API Key，也不复制登录文件或令牌。界面的文本模型名称仅标识这条本机通道，实际执行由 CLI 默认模型决定，不保证固定为某个版本。

## 图片比较分支预览

在 `codex/image-compare` worktree 双击根目录的 `启动图片比较版.cmd`，或执行 `powershell -NoProfile -File local/Start-ImageCompare.ps1 -NoBrowser`。前端来自当前 worktree，地址为 `http://127.0.0.1:3040/canvas`，身份接口为 `/__image-compare`。复用主检出 3002 的共享数据、Krita、Blender 与 Codex 服务，以及现有 ComfyUI；在预览中保存会更新同一份共享数据。

入口核对依赖锁文件并复用主检出的 node_modules；验证分支身份、共享数据和 Krita 状态接口。重复启动复用本入口服务，3040 被其他进程占用时退出，不终止别的服务。日志位于本 worktree `.local/image-compare-*.log`。

使用：从「扩展节点」添加「图片比较」，将两个图片来源连接到左侧输入，单击节点，在下方小面板指定 A、B；滑杆常驻节点下方并与图片等宽，滑块中心对齐分割线。滑杆模式左侧 A、右侧 B，两图等比铺满同一视框，比例不同时裁边。使用加减按钮同步缩放、拖动画面同步平移；不做自动对齐。在小面板选定 A 或 B 后，右侧输出可连接生成配置或图像写回节点。缩放与平移是临时查看状态；来源、模式和输出选择随画布保存。源图生成中、删除或断线时无有效输出，不会沿用旧图。
