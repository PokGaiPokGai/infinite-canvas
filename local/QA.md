# 验收数据与执行约定

## 可重复行为检查

在任意已安装独立依赖的检出运行 `pnpm --dir web run check`。Node 测试使用标准 `node:test`；TypeScript 加载器只处理测试环境的路径别名、转译和浏览器配置，不对运行代码打补丁。Python 普通检查仅运行不依赖 Blender 的离线项目。

批处理矩阵、冻结参数、引用角色、流程复制与节点引用重映射、循环拒绝、版本保护、跨窗口所有权及载入状态都有仓库内回归。真实像素效果、模型调用、真实 Krita/Blender 和浏览器交互仍需要对应验收，不能由这些测试替代。

## 数据隔离

- 单元测试使用纯内存节点。需要 SQLite 或文件的新增测试通过 `withTestDirectory` 创建系统临时目录，清理时核对绝对路径、前缀和本次归属标记；不得传入用户数据目录。
- 浏览器验收使用独立临时浏览器配置与测试数据。需要本机共享协议时，启动只接测试数据库的模拟服务；不能把默认 3002 或现有共享画布作为夹具。
- 不以现有用户画布标题作为可覆盖的测试标识。故意失败的节点、测试模板和错误消息只在测试环境使用。
- 验收结束关闭自己创建的浏览器和服务，保留必要日志；不能关闭用户窗口。

## 已存在的旧验收画布

此前的“第一批／第二批验收”等记录已进入旧共享数据库，可能已被用户继续编辑。此次代码整改不按标题自动删除这些记录。后续整理时先逐项核对内容、导出完整画布及关联素材，再按确认的对象删除；不得以“测试”二字做批量删除条件。

## 外部集成

`local/blender-commands.test.py` 依赖真实 Blender 的 `bpy`，仅在新建的隔离 Blender 进程内执行；不得发送到用户当前场景。对已有 BlenderMCP、Krita 或生成渠道的真实验收单独记录对象、行为、结果和限制。自动检查不会创建付费生成请求。
