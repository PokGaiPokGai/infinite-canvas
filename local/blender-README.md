# Blender Link 第一版

本机画布复用已安装的 **BlenderMCP**。不新增 Blender 插件，不注册常驻的定时检查；BlenderMCP 负责将请求放到 Blender 主线程执行。

## 打开本分支预览

双击 worktree 根目录的 `启动Blender分支预览.cmd`，或在 worktree 运行 `powershell -NoProfile -ExecutionPolicy Bypass -File local/Start-BlenderPreview.ps1`，然后打开 `http://127.0.0.1:3034/canvas`。

当前 `codex/blender-canvas-v2` 从已合并 Blender 第一版的本地 `main` 创建。该入口使用本 worktree 的 Vite 前端和 Blender 桥接代码，不需要先构建；锁文件一致时复用主目录已安装的依赖，不安装新包。前端使用 3034，独立 Blender 接口使用 3036，快照与回执保存在本 worktree 的 `.local/blender-link/`。端口已被其他程序占用时直接报错，不停止其他进程。

画布、原图、渠道配置与生成历史通过原本机 3002 服务读取同一份共享数据库，Krita 与 Codex 桥接也沿用该服务，ComfyUI 仍使用已有的 8188。两边保存影响同一份本机数据，既有冲突保护继续生效。共享服务未运行时调用主检出启动器；本分支不创建空白数据库，不复制渠道配置或登录文件。

原第一版的 3030／3032 预览继续保留其独立测试数据库；当前入口不会导入或修改那份测试数据。日志和进程归属记录位于本 worktree 的 `.local/blender-preview/`。重复启动检查目录归属并复用当前服务；启动时核验共享存储和 Krita 状态，Krita 未连接时仍可进入画布。

## 手动工作流

1. 打开 Blender，在右侧 **MCP for Blender** 面板启动现有服务，默认地址为 `127.0.0.1:9876`。若修改了 Blender 中的端口，在任一 Blender 节点小面板填写相同的「BlenderMCP 端口」并点击「连接」，或按回车；地址始终为本机 `127.0.0.1`。
2. 在本机画布添加 **Blender Link**，保持「读取」，点击节点，在小面板的「选择视口」中选择具体视口或「最近渲染结果」，节点会自动读取一次。已有视口绑定时，从「写回」切回「读取」也会自动更新一次；未绑定时先选择视口。节点右下角的刷新箭头继续支持手动读取，小面板关闭后也可使用；读取期间箭头旋转且禁止重复点击。节点保存 PNG 原图，可连接通用「生成配置」。
3. 添加第二个 Blender Link，切到「写回」，连接图片或生成配置的已选图片输出。默认「更新已有贴图」直接列出工程里的可编辑普通图片，不要求图片属于任何材质；选中后显示当前缩略图、尺寸和引用数。
4. 也可选择「新建图片」并填写名称，将结果加入工程图片列表；或选择「替换材质节点」，再选材质及其顶层图像纹理节点，沿用原来的局部替换方式。
5. 选择颜色（sRGB）或数据（Non-Color）用途，将鼠标移到写回节点上或选中节点，点击节点下方的「写回当前图片」（新建方式显示「新建并写入」）。关闭小面板也可执行；没有有效输入或目标时禁用，成功后同一输入不可重复点击。图片按输入 PNG 的尺寸写入并打包，最后由用户保存 `.blend`；不会覆盖磁盘上的原图片文件。

三种方式的区别：

- **更新已有贴图**：直接覆盖所选 Image 数据块的像素，保留身份、名称及引用关系，所有引用它的材质／节点一起更新。不创建「写回前」图片，无引用目标保留 Fake User。若预览后目标像素、尺寸、色彩用途等发生变化，拒绝覆盖，需放弃旧指令、刷新后重新写回。旧版本已经创建的备份不会自动删除。
- **新建图片**：只创建并打包一张图片，不自动分配材质；保留 Fake User，因此无材质引用也可随 `.blend` 保存。同名由 Blender 自动区分，回执显示实际名称。
- **替换材质节点**：新建打包图片，仅替换所选节点的图片引用；旧图片保留 Fake User。共享该材质的对象一起更新，其他引用旧图的节点仍使用旧图。

已有贴图列表包含可编辑的文件图片和 Blender 内新建图片；不列 Render Result、Viewer、UDIM、序列、视频、多视图及不可编辑的链接图片。缩略图仅在选中、打开面板或手动刷新时读取，不定时扫描。新增图片名称只用于 Blender 数据块，不接受浏览器指定的文件路径。

端口设置由当前分支服务保存在被忽略的 `.local/blender-link/connection.json`，所有 Blender 节点共用，页面和服务重启后保留。只接受 1–65535 的整数，不扫描其他端口；点击「连接」会保存端口并重新读取服务状态，失败时显示实际地址，端口设置仍保留。读取与写回节点右下角均同步显示已保存端口，使用 Blender 橙色与 40% 不透明度；读取模式下端口位于刷新箭头左侧。输入框里的未保存草稿不改变节点标签。

节点使用 Blender 官方图标与橙色动态边框，沿用 Krita Link 的选中加粗、流光与减少动画设置。节点保持预览图片比例，读写切换直接位于节点上。错误和连接详情只在小面板显示。自动读取只由选择视口和切回读取模式触发，打开面板或重载画布不会再次截图；读取失败后由用户手动刷新。读取期间若视口或连接已变化，旧结果不覆盖当前绑定。生成和写回仍由用户手动执行，重新打开画布不自动重新写入。写回成功后，右侧输出才提供本次冻结的输入原图。

视口读取保留所选视口的视角及着色效果；最近渲染结果读取已有的 Render Result，不启动渲染。图片沿用纹理节点既有映射，**没有实现相机投影或 UV 烘焙**。

## 连接与恢复

- 前端仅调用本机 `/blender-link` 接口，由已有 Node 服务转发到 BlenderMCP；浏览器不能提交任意 Python、文件路径或远程主机地址。
- 只接受本机画布来源和专用请求头。固定 Python 操作保存在 `blender-commands.py`，PNG 原图、快照和写回回执保存在被忽略的 `.local/blender-link/`。
- 沿用当前已安装 BlenderMCP 客户端的 180 秒接收等待，不自动重试。超时或连接中断不代表操作一定未执行；使用「查询／重试同一指令」恢复原指令，不更换输入或目标。
- 提交前冻结图片、写回方式与目标，并保存待确认指令；同一指令不能改图片、目标、新建名称或色彩用途。Blender 打开另一份文件或重启后，会拒绝旧会话的新操作；不会按名称静默绑定另一图片或材质。
- 待确认写回同时冻结端口。切换端口后不能把旧指令转发给新服务，需要恢复原端口再重试；已经成功的回执仍可查询，不重复执行写入。
- 已成功指令的回执在本机保存；重复查询返回原回执，不再次写入。Blender 内的撤销或用户后续改动不会自动重放旧指令。
- 放弃待确认指令前，应先在 Blender 核对是否已写入。放弃仅解除画布等待，不撤销 Blender 已完成的修改。
